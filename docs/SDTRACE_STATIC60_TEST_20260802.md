# SDTRACE 静止60秒ログ試験 — 実施記録

実施日: 2026-08-02

## 実施条件

- 対象: CoreS3 の現行 SDTRACE ファームウェア（SD SPI 10 MHz のまま）。
- microSD、SDクロック、SDバッファ、mutex、Web処理、BIN/TXTログ形式は、この試験中に変更していない。
- 静止状態で、`POST /api/log/start?duration_s=60` を1回だけ送信した。
- 開始応答: 2026-08-02 13:44:41 JST（04:44:41 UTC）、HTTP 202、`{"logging":true,"duration_s":60,"bno_capture":false}`。

## 観測結果

- 後続のシリアル診断には `log=0`、`rec=7971`、`q=3`、`final=0` が繰り返し記録された。
- 停止API（13:46:57 JST）は HTTP 200、`{"logging":false}`。この呼出し時点で既に停止していたかは、開始から停止までのシリアル欠落のため断定できない。
- 終了後のファイル一覧では `RUN0003.BIN` は 0 byte、`RUN0003.TXT` は存在しなかった。BINはPCへ0 byteのまま回収した。TXT取得はHTTP 404だった。
- 捕捉済みシリアルには CMD18/CMD0D/CMD00、`sd_diskio.cpp`、`Card Failed!`、`SD write failed`、`SDTRACE` の行は**ない**。これは「エラーなし」を意味しない。下記の取得欠落により、最も重要な開始〜停止区間を記録できていない。
- `vfs_api.cpp ... RUN0003.TXT does not exist` の1行は、存在しないTXTをダウンロード確認したときの副作用であり、SD CMDエラーではない。

## 取得の完全性（重要）

USBリセット直後の生シリアル取得ではROM起動ログだけを受信し、USB再列挙後のアプリ出力を受信できなかった。取得方式を切り替えた時点では、ログ開始〜自動停止およびSDTRACEダンプが既に通過していた。そのため次は保存できたが、ユーザー指定の「起動から試験終了までの完全なシリアルログ」および「SDTRACE全行」は満たしていない。

- 起動ROMログ: 保存済み。
- アプリ診断: 試験終了後の断片のみ保存済み。
- SDTRACE: 捕捉行0。
- SDライブラリCMD行: 捕捉行0。
- 画面表示: CoreS3表示をPCから取得する経路がなく、写真/スクリーンショットは未取得。

これは試験データの改変ではなく、取得経路の失敗として保存する。ユーザー指定どおり、この記録の後に再試験、SDカード操作、ファームウェア設定変更は行っていない。

## 保存物

`pc-tools/boat_eskf/captures/` の `SDTRACE_STATIC60_20260802_*` を参照する。

- `SERIAL.log`: ROM起動ログ（生）。
- `APP_SERIAL.log`: 試験終了後のアプリ診断（生）。
- `APP_SERIAL_DECODED.log`: 診断内の文字列 `\\n` を改行として表示した閲覧用コピー。
- `SERIAL_COMBINED.log`: 上記2つを欠落区間の明示マーカー付きで連結した閲覧用コピー。
- `SDTRACE.log`: 捕捉できたSDTRACE行の全件（0行であることを明記）。
- `SD_LIBRARY_CMD.log`: 捕捉できたSDライブラリCMD行の全件（0行であることを明記）。
- `WEB.log`: 開始、停止、状態一覧、BIN/TXT回収のHTTP応答。
- `RUN0003.BIN`: HTTP回収した生成BIN（0 byte）。
- `ARTIFACT_STATUS.md`: TXT不在と画面未取得を含む保存物の状態。

## 判定

この1回は「60秒要求を送ったSDTRACE付き静止試験」としては実施済みであるが、CMDエラー発生時のSD操作順序を捕捉するという目的に対しては**不成立**である。SDTRACEが出力された可能性がある区間をシリアルで取り逃したため、ソフトウェア経路・カード/ハードウェアのどちらとも判定しない。
